# INV-3830 — Tickets Home

- **Ciclo:** 10
- **Produto:** Portal
- **Tipo de registro:** Snapshot de clarificação de task
- **Snapshot:** 2026-08-24
- **Situação no snapshot:** implementação validada; PR aberta e em revisão

## Autoridade e atualidade

Este registro é memória histórica de planejamento. O Linear é canônico para os dados atuais de
execução. Portal API possui o contrato de lista e suas invariantes; Portal Web possui apresentação e
interação. Revalide a issue, o contrato merged da API e a base atual da Web antes de alterar a task.

## Clarificação durável

Tickets Home é uma superfície de leitura com escopo de organização, não uma visualização apenas do
navegador
sobre uma página de dados de Ticket. Um solicitante autorizado vê os Tickets da organização ativa,
contadores globais estáveis, filtros por estado processados no servidor, paginação, um marcador
visível de atenção
e uma ação na linha que abre o mesmo endereço de Ticket Detail usado por links diretos e
notificações.

## Decisões preservadas

- A lista cobre toda a organização para um usuário autorizado. O acesso não se limita aos Tickets
  criados pelo solicitante atual.
- Portal API permanece canônica para taxonomia de estados, totais dos contadores, filtros, semântica
  de busca, ordenação e paginação.
- Seis contadores de apresentação podem agrupar os sete estados canônicos sem alterar o modelo
  persistido de ciclo de vida.
- O filtro deve ocorrer no servidor. Filtrar somente a página de offset atual faria linhas,
  contadores e paginação divergirem.
- `Waiting on you` recebe um marcador semântico que os testes podem verificar sem depender da cor.
- A tabela exibe a referência pública do Ticket e campos visíveis ao solicitante. Ela não expõe dados
  internos do Linear nem do Labs.
- Selecionar uma linha navega para uma URL estável de detail, em vez de depender de um objeto em
  memória.

## Limites e dependências

- A INV-3828 possui e publica o domínio de Ticket e os contratos de lista/detail. A Web não deve
  redefinir DTOs nem enums localmente.
- A INV-3831 possui resolução do detail, timeline, comportamento do overlay e ações de ciclo de vida
  do solicitante.
- Busca, filtros de estado, página e seleção de linha devem sobreviver à navegação de acordo com o
  contrato final de rota.
- Achados de polimento visual e dívidas de localização ou do test harness do repositório são
  follow-ups, salvo se o Linear os adicionar explicitamente à issue.
