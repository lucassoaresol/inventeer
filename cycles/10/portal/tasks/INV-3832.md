## Authority and freshness

This record preserves the contract delivered by INV-3832. Linear and the current Portal authority
model remain canonical. A later proposal about System Admin access was not folded retroactively into
this task and must be revalidated through its own issue and approved product contract.

## Durable clarification

Metrics access uses the atomic organization-scoped permission
`portal.client.metrics.view`. It is individually granted, has no default role grant, and fails closed
in both navigation and route access while permissions load, when resolution fails, or when the
permission is absent.

## Decisions preserved

- Metrics does not reuse `portal.client.delivery.view`.
- The existing User & Role Management flow grants and revokes access; INV-3832 does not add another
  provisioning UI or script.
- Menu visibility and route protection are user-experience and defense-in-depth controls. Data
  authorization remains server-side.
- The positive authorized path and the loading, error, no-context, and no-permission paths are all
  distinct acceptance cases.
- INV-3832 owns the permission contract, menu entry, route shell, and guard. It does not absorb the
  Metrics BFF or tab-specific data semantics.
- The System Admin request to view Metrics across organizations requires an explicit organization
  observation model, navigation behavior, and API authorization contract. It is a separate product
  change, not a guard exception.

## Boundaries and dependencies

- Permission-catalog synchronization between API and Web, production-route test fidelity, and the
