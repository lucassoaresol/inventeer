## Durable clarification

INV-3847 wires Ticket lifecycle events into the existing notification infrastructure. Each applied
requester-visible lifecycle occurrence produces one typed notification for the Ticket requester,
with transactional consistency, occurrence-level idempotency, and a tenant-safe entity reference.

## Decisions preserved

- Reuse the existing NotificationService, table, REST surface, and append-only catalog; do not create
  another notification mechanism.
- The recipient is the authoritative Ticket requester, not the actor, approver, or a browser-provided
  identity.
- Notification copy is rendered client-side from typed payloads; persisted `title/body` text is not
  reintroduced.
- `entity_type = ticket` and the entity ID resolve the same tenant-safe Ticket Detail resource used
  by list navigation.
- Idempotency is keyed by immutable event occurrence. Retry of one event deduplicates, while two
  legitimate occurrences remain two notifications.
- Ticket transition and notification persist or roll back together in the v1 transaction boundary.
- Concurrent mutations of the supporting DoD dataset are serialized so distinct lifecycle events
  cannot overwrite one another.
- Cross-organization navigation reuses the existing active-context selection and authorization; no
  automatic tenant switch or bypass is introduced.
